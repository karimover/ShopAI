# Техническое задание — ShopAI

**Проект:** «Разработка платформы по созданию интернет-магазинов с ИИ-помощником».

**Версия:** описание текущего MVP.

## 1. Назначение проекта

ShopAI — веб-сервис, который помогает начинающему предпринимателю или небольшому бренду создать базовый интернет-магазин без самостоятельной разработки.

Сервис объединяет в одном рабочем пространстве:
- создание аккаунта и магазина;
- добавление и управление товарами;
- подготовку описаний и SEO-заголовков с AI;
- создание текстовой и визуальной конфигурации витрины с AI;
- предпросмотр, ручное редактирование и публикацию сайта;
- корзину, заявки покупателей и управление заказами.

AI формирует черновики и настройки, а владелец проверяет и утверждает результат.

## 2. Целевая аудитория

1. Начинающие предприниматели, которым нужен первый интернет-магазин.
2. Малый бизнес, который продаёт через социальные сети и хочет перейти к собственной витрине.
3. Небольшие бренды и самозанятые, которым важно быстро наполнять каталог и управлять заказами.

## 3. Роли пользователей

### 3.1. Посетитель / покупатель

Может:
- открывать опубликованную витрину;
- просматривать опубликованные товары;
- добавлять товары в корзину;
- отправлять заявку на заказ с контактными данными.

Покупатель не имеет доступа к кабинету владельца и закрытым данным магазина.

### 3.2. Владелец магазина

Может:
- зарегистрироваться, войти и выйти;
- управлять своим магазином;
- создавать, редактировать, искать и удалять товары;
- загружать фотографии товаров;
- использовать AI-помощник карточек;
- создать сайт через AI-конструктор, отредактировать и сохранить его;
- публиковать и снимать с публикации витрину;
- просматривать заявки покупателей и менять их статусы.

В MVP одному аккаунту соответствует один магазин.

### 3.3. Администратор платформы

Отдельная административная роль и интерфейс администратора в текущем MVP не реализованы.

## 4. Основные пользовательские сценарии

### Сценарий 1. Создание магазина
Владелец регистрируется, указывает имя, email, пароль, название и категорию магазина. Система создаёт аккаунт, сессию и магазин.

### Сценарий 2. Наполнение каталога
Владелец добавляет товар, указывает категорию, цену, остаток, описание и фотографию. Товар сохраняется и отображается в каталоге.

### Сценарий 3. AI-подготовка карточки товара
Владелец вводит название и фактические характеристики, выбирает стиль текста и запускает генерацию. Система возвращает черновик описания и SEO-заголовок. Владелец может изменить результат до сохранения.

### Сценарий 4. Создание сайта магазина
Владелец заполняет AI-бриф: название, нишу, аудиторию, ассортимент, отличие магазина, стиль, тон, палитру и язык. Backend отправляет запрос в Cloudflare Workers AI. Ответ проверяется и отображается в предпросмотре. Владелец редактирует тексты и сохраняет конфигурацию сайта.

### Сценарий 5. Публикация и получение заказа
Владелец публикует магазин при наличии опубликованного товара с положительным остатком. Покупатель открывает публичную ссылку, добавляет товар в корзину и отправляет заявку. Владелец видит её в кабинете и меняет статус.

## 5. Логическая схема данных

Текущая реализация хранит данные в JSON-файле `data/shopai.json`. Ниже описаны логические сущности и связи предметной области. Это не Django ORM-модели и не реляционные таблицы.

### 5.1. User — владелец аккаунта

Основные поля:
- `id` — идентификатор;
- `name` — имя владельца;
- `email` — email;
- `passwordHash` — хеш пароля;
- `createdAt` — дата создания.

Связи:
- один User владеет одним Store;
- один User может иметь несколько Session.

### 5.2. Session — сессия пользователя

Основные поля:
- `id`;
- `userId` — ссылка на User;
- `tokenHash` — хеш сессионного токена;
- `expiresAt` — срок действия.

Связь: многие Session относятся к одному User.

### 5.3. Store — интернет-магазин

Основные поля:
- `id`;
- `ownerId` — владелец User;
- `name`, `slug`, `description`, `category`;
- `primaryColor`, `siteConfig`;
- `published`;
- `createdAt`, `updatedAt`.

Связи:
- один Store принадлежит одному User;
- один Store содержит много Product;
- один Store содержит много Order.

### 5.4. Product — товар

Основные поля:
- `id`;
- `storeId` — ссылка на Store;
- `name`, `category`, `description`, `seoTitle`;
- `price`, `stock`, `imageUrl`, `published`;
- `createdAt`, `updatedAt`.

Связь: много Product принадлежат одному Store.

### 5.5. Order — заявка покупателя

Основные поля:
- `id`;
- `storeId` — ссылка на Store;
- `customerName`, `email`, `phone`, `address`, `comment`;
- `items` — массив строк заказа со снимками названия, цены, количества и идентификатора товара;
- `total`, `status`;
- `createdAt`, `updatedAt`.

Связь: много Order принадлежат одному Store. Строки заказа сейчас вложены в массив `items`, отдельной сущности OrderItem в текущем хранилище нет.

### 5.6. Схема связей

```text
User 1 ───── 1 Store
User 1 ───── N Session
Store 1 ──── N Product
Store 1 ──── N Order
Order 1 ──── N items (вложенный массив строк заказа)
```

## 6. Технический стек текущей реализации

- Frontend: React 19, TypeScript, Vite.
- Backend: Node.js 22+ и Express.
- Хранение: JSON-файл с атомарной записью.
- Изображения: локальный каталог `uploads/`.
- Авторизация: сессионная cookie с HttpOnly и SameSite=Lax; пароль хешируется через scrypt.
- AI: Cloudflare Workers AI через OpenAI-совместимый Chat Completions API.
- Тестирование: Node.js built-in test runner, CI проверяет синтаксис backend, API-тесты и сборку frontend.

## 7. Внешние интеграции

### Cloudflare Workers AI

Серверный API используется для:
- генерации описаний и SEO-заголовков карточек товаров;
- генерации контента и конфигурации AI-конструктора сайта.

Секреты хранятся в переменных окружения:
- `CLOUDFLARE_ACCOUNT_ID`;
- `CLOUDFLARE_API_TOKEN`;
- `CLOUDFLARE_AI_MODEL`.

Токен не передаётся в браузер и не хранится в Git.

## 8. Ограничения MVP

В текущем объёме не реализованы:
- онлайн-оплата и эквайринг;
- интеграции служб доставки и расчёт доставки;
- собственные домены;
- полноценный drag-and-drop редактор;
- независимые шаблоны со свободным изменением структуры;
- несколько владельцев и командные роли;
- отдельная административная панель платформы;
- production-реляционная база данных.

Оформление заказа создаёт заявку, а не платёжную транзакцию.

## 9. Критерии приёмки MVP

1. Пользователь может зарегистрироваться, войти и выйти.
2. Владелец управляет только своим магазином, товарами и заказами.
3. Владелец может добавлять, изменять, искать и удалять товары.
4. Фотографии допустимых форматов и размера загружаются и отображаются.
5. AI-помощник создаёт редактируемый черновик описания и SEO-заголовка.
6. AI-конструктор принимает бриф, создаёт структурированный контент, показывает предпросмотр и сохраняет `siteConfig`.
7. Опубликованная витрина открывается по slug и показывает товары.
8. Покупатель может отправить заявку из корзины.
9. Владелец видит заявку и меняет её статус.
10. Остаток уменьшается при создании заявки и возвращается при отмене.
11. Автоматические тесты и production build завершаются успешно.

## 10. Изменения в ходе реализации

Первоначальный план проекта уточнялся по мере реализации. Текущая версия использует React + TypeScript + Node.js + Express и JSON-хранилище. AI-провайдер — Cloudflare Workers AI. AI-конструктор формирует структурированную конфигурацию и контент, которые отображаются управляемым React-шаблоном.

**Важно для согласования требований курса:** отдельный файл требований курса `REQUIREMENTS(1).md` описывает обязательный стек Python/Django, Django ORM, Django Forms и Django Admin. Текущая реализация ShopAI этим требованиям не соответствует, поскольку построена на Node.js/Express и React. Если эти требования применяются именно к ShopAI, необходимо заранее согласовать допустимость текущего стека или спланировать отдельную миграцию backend на Django. Нельзя заявлять, что Django-критерии выполнены.
