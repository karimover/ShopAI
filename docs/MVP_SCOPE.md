# ShopAI — границы MVP и критерии приёмки

## 1. Продукт

ShopAI — платформа для создания интернет-магазина с AI-помощником. Целевая аудитория: начинающие предприниматели, малый бизнес, который продаёт через социальные сети, и небольшие бренды.

Ценность: пользователь без навыков программирования может создать базовый магазин, подготовить каталог и тексты с помощью AI, опубликовать витрину и получать заявки на заказы в одном рабочем пространстве.

## 2. Главный принцип интерфейса

Главный экран после входа — мастер запуска магазина. Он показывает последовательность действий: основная информация, добавление товаров, AI-подготовка контента, создание сайта и публикация. На первом плане — реальные действия по созданию магазина, а не демонстрационная выручка и вымышленные KPI.

## 3. AI-конструктор сайта

Пользователь открывает раздел «AI-конструктор», задаёт название магазина, нишу, ассортимент, аудиторию, отличие бренда, стиль, тон, палитру и язык.

Backend отправляет бриф в Cloudflare Workers AI через серверный OpenAI-совместимый Chat Completions API. Модель возвращает JSON с текстом первого экрана, описанием бренда, CTA, SEO-полями и преимуществами. Backend проверяет структуру ответа и отбрасывает пустые или шаблонные значения.

Frontend показывает live-предпросмотр. Пользователь может вручную отредактировать основные тексты, преимущества и поддерживаемые параметры оформления. После сохранения конфигурация `siteConfig` хранится в магазине. Публичная витрина отображает её в контролируемом React-шаблоне. Произвольный HTML/JavaScript от модели не исполняется.

Если Cloudflare не настроен или недоступен, AI-конструктор сообщает об ошибке и не создаёт видимость успешной генерации.

## 4. AI-помощник карточки товара

Пользователь передаёт название, категорию, характеристики и тон текста. Backend запрашивает Cloudflare Workers AI и получает черновик описания и SEO-заголовка. Владелец проверяет и редактирует результат перед сохранением.

Если Cloudflare не настроен, для карточки товара доступен явно обозначенный demo-режим. Этот режим не является ответом внешней LLM.

## 5. Сквозной сценарий MVP

1. Владелец регистрируется и создаёт магазин.
2. Добавляет товар: название, категорию, описание, цену, остаток и фотографию.
3. При необходимости генерирует описание и SEO-заголовок с AI.
4. Проверяет, редактирует и сохраняет результат карточки товара.
5. Открывает AI-конструктор и заполняет бриф магазина.
6. Генерирует сайт, изучает предпросмотр, правит тексты и сохраняет `siteConfig`.
7. Публикует магазин по адресу `/shop/:slug`.
8. Покупатель открывает витрину, добавляет товар в корзину и отправляет заявку.
9. Владелец видит заявку в кабинете, меняет статус; остаток учитывается.

## 6. Функциональные требования и критерии готовности

| ID | Функция | Критерий приёмки |
|---|---|---|
| MVP-01 | Регистрация и вход | Создание аккаунта, вход и выход; приватные API без сессии возвращают 401 |
| MVP-02 | Магазин | Один магазин на аккаунт; владелец меняет базовые настройки |
| MVP-03 | Каталог | Владелец создаёт, редактирует, ищет и удаляет свои товары |
| MVP-04 | Фотографии | PNG/JPEG/WebP до 4 МБ загружаются и отображаются |
| MVP-05 | AI-конструктор сайта | Бриф → ответ LLM → предпросмотр → ручное редактирование → сохранение `siteConfig` |
| MVP-06 | AI-контент | По названию, категории и характеристикам создаются описание и SEO-заголовок; результат редактируемый |
| MVP-07 | AI-безопасность | Запрос выполняется на backend; токен отсутствует во frontend; demo-режим явно обозначен |
| MVP-08 | Публикация | Опубликованный магазин доступен по slug; неопубликованный магазин не показывается |
| MVP-09 | Корзина и заказ | Покупатель отправляет заявку; сервер проверяет остаток и считает сумму по серверным ценам |
| MVP-10 | Кабинет заказов | Владелец видит свои заявки и меняет статус |
| MVP-11 | Остатки | При создании заявки остаток уменьшается; при отмене возвращается |
| MVP-12 | Изоляция данных | Владелец не читает и не меняет данные другого владельца |
| MVP-13 | Адаптивность | Кабинет и витрина доступны на мобильных и desktop-экранах |

## 7. Что не входит в MVP

Онлайн-оплата и эквайринг; доставка; самостоятельный drag-and-drop редактор; произвольный HTML/CSS/JS; независимые шаблоны с разной структурой; собственный домен; несколько сотрудников и расширенная ролевая модель; складские операции; промокоды; возвраты денежных средств; расширенная аналитика.

Заказ в MVP — заявка без онлайн-оплаты.

## 8. AI-критерии качества

AI должен опираться на факты, которые ввёл пользователь. Нельзя выдумывать материалы, размеры, сертификаты, гарантии, страну производства, отзывы, скидки и обещания доставки.

Пользователь проверяет и редактирует результат до публикации. Целевой показатель паспорта проекта — не менее 90% корректных AI-ответов на типовые запросы. Он может быть заявлен как достигнутый только после оценки документированного тестового набора.

В отчёте фиксируются реально использованные модели и инструменты, этапы, объём сгенерированного материала, человеческие изменения, проверки качества и соблюдение лицензий.

## 9. Ограничения текущей реализации

- Frontend: React 19 + TypeScript + Vite.
- Backend: Node.js + Express.
- Хранилище: JSON-файл на сервере, без Django ORM и без отдельной SQL-СУБД.
- AI: Cloudflare Workers AI; реальный вызов выполняется на сервере.
- Заказ — заявка без онлайн-оплаты.
- Платёжные сервисы и доставка не подключены.
- Нагрузочная проверка на 500 пользователей и измерение целевых показателей ещё не выполнены.

JSON-хранилище предназначено для учебного MVP и одного экземпляра backend. Перед production нужны PostgreSQL, миграции, транзакции, резервное копирование и дополнительные меры защиты.

## 10. Готовность MVP

MVP можно демонстрировать, когда:
- автоматические тесты и production build проходят;
- ручной сквозной сценарий подтверждён на чистом тестовом аккаунте;
- AI-конструктор создаёт реальный контент через подключённую модель;
- сохранённая конфигурация отображается на опубликованной витрине;
- заявка с витрины появляется в кабинете владельца.

Непройденные ручные проверки остаются отмеченными как незавершённые.
