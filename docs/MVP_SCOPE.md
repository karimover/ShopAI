# ShopAI — границы MVP и критерии приёмки

## 1. Продукт

ShopAI — платформа для создания интернет-магазинов с AI-помощником. Целевая аудитория: начинающие предприниматели, малый бизнес, продающий через социальные сети, и небольшие бренды.

Ценность: пользователь без навыков программирования может создать базовый магазин, подготовить каталог с помощью AI, опубликовать витрину и получить заказ в одном рабочем пространстве.

## 2. Главный принцип интерфейса

Главный экран после входа — мастер запуска магазина. Он показывает прогресс создания: основная информация, добавление товаров, AI-подготовка карточек, настройка и публикация витрины. На первом плане должны быть действия по созданию магазина, а не аналитика продаж. Демонстрационные выручка, заказы, графики и KPI не являются частью MVP и не должны отображаться как реальные данные.

## 3. Сквозной сценарий MVP

1. Владелец регистрируется и задаёт название/категорию магазина.
2. Добавляет товар: название, категория, описание, цена, остаток, фотография.
3. При необходимости вызывает AI-помощника: передаёт название и характеристики, выбирает стиль, получает описание и SEO-заголовок.
4. Проверяет, редактирует и сохраняет результат в карточке товара.
5. Настраивает название, описание, категорию и цвет витрины.
6. Публикует магазин по адресу /shop/<slug>.
7. Покупатель открывает витрину, добавляет товар в корзину и отправляет заявку на заказ с контактными данными.
8. Владелец видит заказ в кабинете и меняет его статус; остаток товара учитывается.

## 4. Функциональные требования и критерии готовности

| ID | Функция | Критерий приёмки |
|---|---|---|
| MVP-01 | Регистрация и вход | Пользователь создаёт аккаунт, входит и выходит; приватные API без сессии возвращают 401 |
| MVP-02 | Магазин | На аккаунт создаётся один магазин; владелец изменяет базовые настройки |
| MVP-03 | Каталог | Владелец создаёт, редактирует, ищет и удаляет свои товары |
| MVP-04 | Фотографии | PNG/JPEG/WebP до 4 МБ загружаются и отображаются |
| MVP-05 | AI-контент | По названию, категории и характеристикам формируются описание и SEO-заголовок; результат редактируемый |
| MVP-06 | AI-безопасность | Запрос к внешней модели идёт через backend; ключ не передаётся в браузер; demo-режим маркируется |
| MVP-07 | Публикация | Опубликованный магазин доступен по slug; черновик недоступен |
| MVP-08 | Корзина и заказ | Покупатель оформляет заявку; сервер проверяет наличие и рассчитывает сумму по серверным ценам |
| MVP-09 | Кабинет заказов | Владелец видит свои заказы и может менять статус |
| MVP-10 | Остатки | При создании заказа остаток уменьшается; при отмене возвращается |
| MVP-11 | Изоляция данных | Владелец не может читать/изменять товары, магазин или заказы другого владельца |
| MVP-12 | Адаптивность | Кабинет и публичная витрина доступны на мобильном и desktop экранах |

## 5. Что не входит в MVP

Онлайн-оплата и эквайринг; доставка; несколько тем/шаблонов и визуальный редактор; собственный домен; несколько сотрудников и расширенная ролевая модель; складские операции, промокоды, возвраты денег, расширенная аналитика; масштабирование на 500 одновременных пользователей.

Заказ — заявка без онлайн-оплаты.

## 6. AI-критерии

AI нужен для сокращения ручной работы при создании карточек товаров. Генератор должен опираться на данные пользователя и не выдумывать материалы, размеры, сертификаты, гарантию или свойства.

Пользователь проверяет и редактирует результат до публикации. Целевой показатель из паспорта проекта — не менее 90% корректных ответов на типовые запросы; он должен быть подтверждён тестовым набором, а не заявлен заранее.

В отчёте нужно указать фактически использованные инструменты/модели, этапы и объём сгенерированного материала, человеческие доработки, проверки качества и соблюдение лицензий.

## 7. Ограничения текущего MVP

Сервер использует JSON-файл как простое локальное хранилище. Это учебное решение для одного экземпляра backend, не production-ready база данных. Перед публичным запуском требуются PostgreSQL, миграции, резервные копии и дополнительное тестирование.

Реальная LLM работает только при настройке серверных переменных провайдера. Без них включается маркированный demo-генератор. Платежей и доставки нет; заказ является заявкой.

## 8. Готовность MVP

MVP готов к демонстрации, когда тестировщик проходит весь сценарий из раздела 2 на чистом аккаунте, автоматические API-тесты и production build завершаются успешно. Непройденные ручные проверки остаются отмеченными как незавершённые.
