# ShopAI — структура презентации контрольной точки

## Слайд 1. ShopAI

Платформа для создания интернет-магазинов с AI-помощником. Заказчик: ООО «НОРМОКОНТРОЛЬ».

## Слайд 2. Проблема и решение

Запуск магазина требует настройки витрины, подготовки каталога, описаний и организации заказов. ShopAI объединяет эти задачи в одном рабочем пространстве. AI помогает готовить товарный контент, который пользователь проверяет перед сохранением.

## Слайд 3. Целевая аудитория

- Начинающие предприниматели.
- Малый бизнес, продающий через социальные сети.
- Небольшие бренды и самозанятые.

Ценность: создать базовый интернет-магазин без самостоятельной разработки и быстрее подготовить каталог.

## Слайд 4. Конкурентный анализ

Сравнение Shopify, Tilda и Ecwid. Все аналоги предлагают базовые e-commerce-функции; Shopify и Ecwid также описывают AI-инструменты для карточек. Гипотеза ShopAI — единый guided-сценарий создания магазина с AI на этапе подготовки контента.

## Слайд 5. Сценарий MVP

Регистрация → магазин → каталог → AI-контент → публикация витрины → корзина → заказ в кабинете владельца.

## Слайд 6. Демонстрация MVP

Показать:
- регистрацию/вход и кабинет владельца;
- создание и редактирование товара, фото и остаток;
- AI-черновик описания и SEO с возможностью редактирования;
- публикацию витрины;
- оформление тестового заказа и изменение статуса в кабинете.

Важно: без настройки внешнего AI-провайдера используется демонстрационный режим. Заказ — заявка без онлайн-оплаты.

## Слайд 7. Архитектура текущего MVP

Frontend: React + TypeScript + Vite.
Backend: Node.js + Express.
Хранилище: JSON-файл на сервере.
Авторизация: хеширование пароля и HttpOnly session cookie.
Файлы: загрузка фото в локальное хранилище.
AI: серверный адаптер к OpenAI-compatible API; демо-режим по умолчанию без секретного ключа.

Ограничение: JSON-хранилище — учебное MVP-решение. Для production нужна PostgreSQL, миграции и резервное копирование.

## Слайд 9. Метрики успеха

Целевые критерии паспорта проекта:
- Создание и публикация магазина новичком — не более 60 минут.
- Корректность AI на типовых запросах — не менее 90%.
- 500 одновременных пользователей.
- Время отклика страниц — не более 2 секунд.
- Два платёжных сервиса и одна доставка.
- Не менее 95% тест-кейсов без критических дефектов.

Не представлять эти значения как достигнутые до измерения.

## Слайд 10. Результаты и дальнейшие шаги

Текущий MVP поддерживает аккаунт владельца, один магазин, каталог, фото, AI-черновики, публичную витрину и заказ-заявку. Автоматические API-тесты и production build проходят успешно; ручные проверки требуется завершить.

Следующие шаги: подключить выбранную LLM, заменить JSON-хранилище на PostgreSQL, проверить MVP с пользователями, затем развивать конструктор, платежи, доставку и аналитику.

## Примечание для защиты

Не выдавать демонстрационный AI-генератор за подключённую внешнюю LLM. Не называть JSON-файл production-базой данных. Не заявлять о платежах и доставке. Целевые метрики не являются фактическими результатами текущей итерации.
