## Правила командной работы

- Каждая задача получает исполнителя, приоритет, критерий готовности и согласованный срок.
- Каждый участник создаёт отдельную ветку с коротким названием задачи.
- Изменения отправляются через Pull Request в main; прямые коммиты в main не рекомендуются.
- Pull Request описывает изменения, способ проверки и связанную issue.
- Перед объединением проходят CI: серверная синтаксическая проверка, API-тесты и frontend build.
- Не создавать фиктивные коммиты или результаты тестирования.
- AI-вклад указывать прозрачно: инструмент, этап, сгенерированный материал, человеческая проверка и итоговые изменения.
